## 등록 순서

1. 대표 이미지에는 `screenshots/01-cover.png`를 올립니다.
2. `원티드_제출문안.md`의 제목, 해결하고자 한 문제, AI 활용 방식 및 결과를 해당 입력란에 복사합니다.
3. 추가 스크린샷 입력란이 있으면 02 → 04 → 06 → 07 순으로 등록합니다. 모바일 대응을 강조할 때 03, 결정 지도 구현을 설명할 때 05를 추가합니다.
4. 서비스 링크는 https://ai-decision.tetelab.dev 입니다. 이 작업의 변경 사항은 로컬에 반영한 상태이며, 공개 서버 반영에는 별도 커밋·푸시/배포가 필요합니다.
5. 업로드 전에 원티드 폼의 실제 이미지 용량·비율·글자 수 제한을 확인하세요. 첨부된 폼 화면에는 구체적인 제한이 표시되지 않아 임의의 필수 규격으로 단정하지 않았습니다.
6. 원티드 계정 로그인이나 최종 제출은 이 작업에서 수행하지 않았습니다.

## 실제 실행 기록

- 촬영일: 2026-09-03, 한국 시간.
- 수정된 로컬 프런트엔드의 프로덕션 빌드와 최신 백엔드를 연결해 촬영했습니다. 화면 내용을 이미지 편집이나 가짜 API 응답으로 합성하지 않았습니다.
- 처음 선택지 정리는 기본 안내 흐름이며, 이후 후속 질문과 최종 분석은 실제 LLM 응답을 확인했습니다.
- 가상 예제: 새 노트북 구매 / 현재 노트북 수리. 새 제품 140만원, 수리 80만원, 예산 150만원, 매일 업무에 사용, 수리 후 1~2년 예상, 새 제품 보증 1년.
- 가격과 보증 조건은 기능 확인을 위해 입력한 가상 상황이지 실제 제품 조사 결과가 아닙니다.
- 비용 칩과 사용 기간 칩의 클릭 후 사용자 말풍선 → 전송 중 → 실제 AI 후속 응답/분석 준비로 이어지는 것을 확인했습니다.
- 직접 입력 칩은 전송하지 않고 입력창에 포커스만 두는 것을 확인했습니다.
- 최종 응답은 새 제품을 조건부로 추천하면서 수리의 비용 장점, 업무 사양·보증 확인, 수리가 유리해질 조건을 함께 제시했습니다.

## UI 변경과 검증

- 겹쳐 보이던 입력창 테두리/바깥 포커스 링을 단일 내부 둥근 테두리로 변경했습니다.
- 텍스트 입력 영역 자체의 사각형 포커스 outline을 제거했습니다. 키보드 포커스는 폼의 둥근 테두리로 유지합니다.
- 오른쪽 상태 체크리스트와 진행률·설명 텍스트를 확대했습니다.
- 일반 선택지는 즉시 전송됩니다. 우선순위형 선택지는 순서 선택을 마친 뒤 자동 전송됩니다.
- 모바일 390px 화면 검사에서 문서 폭은 375px로 화면을 넘지 않았고, 입력창의 계산된 글씨 크기는 16px, outline은 none이었습니다.
- 이 검사는 브라우저의 모바일 너비 검사입니다. 실제 iPhone Safari의 키보드·핀치 줌을 직접 테스트한 것은 아닙니다.
- 프런트엔드 자동 테스트 13개, lint 및 프로덕션 빌드를 통과했습니다. 전체 서비스의 정확도를 보장하는 성능 평가 수치는 아닙니다.
