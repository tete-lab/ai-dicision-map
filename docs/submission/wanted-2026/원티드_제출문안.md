## 3. AI 활용 방식 및 결과

### 기본 문안

AI Decision Map은 “어느 쪽이 더 좋을까?”라는 고민을 대화로 정리하고, 선택지별 장단점과 다음 행동을 보여주는 의사결정 지원 서비스입니다.

기존의 일반적인 AI 대화는 긴 조언을 읽고 다시 핵심을 정리해야 하거나, “결국 선택은 본인의 몫”이라는 답변으로 끝나기 쉽습니다. 이 서비스는 결정을 대신 내려주기보다, 사용자가 왜 망설이는지와 무엇을 중요하게 여기는지를 드러내고 자신에게 맞는 방향으로 한 걸음 나아가도록 응원하는 데 초점을 맞췄습니다.

LLM은 사용자의 자연어 답변에서 선택지, 판단 기준, 사용자 진술, 가정, 미확인 정보를 구조화합니다. 대화에서 드러난 선호 이유를 함께 보관하고, 다음 질문은 이미 확인한 정보를 되묻기보다 판단에 필요한 조건을 좁히도록 설계했습니다. 일반 답변 칩은 한 번 누르면 바로 전송되고, 직접 입력과 우선순위 선택도 지원합니다. 단순 메뉴 고민은 최대 4문항, 일반 고민은 최대 12문항을 목표로 제한해 입력 부담을 줄였습니다.

분석 단계에서는 LLM과 계산 엔진의 역할을 분리했습니다. 사용자의 상대 선호 점수와 가중치는 서버가 계산하고, LLM은 그 점수를 그대로 풀어 쓰는 대신 사용자 상황과 실제 선택의 효과를 연결해 설명합니다. 결과 화면에는 추천 이유, 각 대안이 적합한 조건, 기대할 장점, 확인할 부담, 지금 할 한 가지, 부담을 줄이는 대안을 먼저 보여줍니다. 구매 고민이라면 바로 사거나 포기하는 이분법을 넘어 수리·체험·보류 같은 방법의 가능성도 검토하도록 구성했습니다.

결정 지도, 비교 요약, AI 인사이트, 액션 플랜을 하나의 결과로 연결했습니다. 점수 비교와 가중치 민감도 그래프는 참고 자료로 제공하며, 점수를 객관적인 품질이나 성공 확률로 표현하지 않습니다. 또한 입력에 없는 근거 인용을 검사하고, AI 분석이 실패하면 이를 숨기지 않고 기본 안내와 재시도 기능을 제공합니다.

현재 대화에서 결과 확인까지 이어지는 웹 앱을 구현했습니다. 사용자의 마음이 향하는 방향을 긍정적으로 설명하되, 비용·안전·불확실성을 숨기지 않는 “응원하는 의사결정 도우미”를 지향합니다. 실제 결정 시간 단축이나 만족도 향상은 향후 사용자 테스트로 검증할 계획이며, 이번 제출에서는 구현된 사용 흐름과 실제 실행 화면을 제시합니다.

### 짧은 버전

AI Decision Map은 결정을 미루는 사용자가 자신의 기준을 정리하고 다음 행동으로 나아가도록 돕는 대화형 의사결정 서비스입니다. LLM이 자연어 고민에서 선택지·우선순위·사용자 진술·가정을 구조화하고, 서버 계산 엔진이 선호 점수를 계산합니다. 결과는 점수 나열 대신 추천 이유, 대안별 장단점, 적합한 조건, 구체적인 액션 플랜을 중심으로 제공합니다. 대화형 칩과 질문 수 제한으로 입력 부담을 줄이고, 결정 지도와 비교 화면으로 차이를 시각화했습니다. 사용자의 선호를 응원하되 위험과 불확실성을 함께 표시하며, 실제 효과는 향후 사용자 테스트로 검증할 예정입니다.

## 5. 구현 설명이 필요할 때

프런트엔드는 Next.js·React·TypeScript, 결정 지도는 React Flow로 구성했습니다. 백엔드는 Kotlin·Spring Boot, 데이터 저장은 MySQL을 사용합니다. AI 응답은 구조화 JSON으로 처리하며, 서버에서 응답 형식과 선택지·근거 참조를 검사합니다. 사용자의 진술과 가정, AI 추론은 구분해 표시합니다.

## 6. 제출 시 과장하지 않을 내용

- 외부 웹 검색, 실시간 가격 비교, 전문가 검증을 수행한다고 적지 않습니다.
- 점수나 입력 충족도를 성공 확률 또는 사실 정확도로 표현하지 않습니다.
- 실제 사용자 연구 없이 결정 시간·만족도 개선 수치를 제시하지 않습니다.
- 모든 자연어 입력을 정확히 이해한다고 단정하지 않습니다. 모호한 후보는 사용자가 명시적으로 확인할 수 있습니다.
- 화면의 저장·공유·PDF 버튼은 아직 연결 예정이므로 완료 기능으로 소개하지 않습니다.
- 캡처의 노트북 가격·상황은 기능 확인을 위한 가상 입력이며 실제 제품 정보가 아닙니다.
