# 맥락 기반 결정 조언

## 결과 생성

- 결정 엔진은 사용자의 상대 선호 점수와 가중치를 계산합니다. 점수는 객관적 품질, 비용 수준, 성공 확률이 아닙니다.
- 결과 화면은 `analyze` 이후 `enrich`가 완료된 다음 열립니다. LLM은 결정 상태의 사용자 진술, 가정, 선호 이유, 미확인 조건과 선택지 전체를 받아 조언합니다.
- 결과 첫 화면은 제안과 이유, 대화 근거, 지금 할 한 가지, 부담을 줄이는 대안을 먼저 보여줍니다.
- 선택지마다 적합한 조건(`bestWhen`), 기대 효과, 확인할 부담을 제공합니다. 비교 점수와 가중치 민감도는 접힌 참고 자료로 유지합니다.
- 구매라면 사용 목적·기존 대체 수단·총비용·사용 빈도·되돌릴 수 있는 조건을 검토합니다. 수리·대여·체험은 확인 없이 이용 가능하다고 단정하지 않습니다.

## 근거와 한계

- `evidenceRefs`는 입력된 사용자 진술/선호 이유의 실제 문자열만 허용합니다. `assumptionRefs`는 입력된 가정/AI 추론만 허용합니다.
- 선택지 ID 전체 일치, 추천 ID 유효성, 추천 근거 유무, 핵심 설명의 숫자 점수 반복 여부를 검증합니다.
- 이 검증은 참조 무결성 검사이지 주장 전체의 사실 검증이 아닙니다. 외부 검색·가격 조회를 수행하지 않습니다. 실생활 정확도 평가는 실제 모델과 다양한 사례로 별도 수행해야 합니다.
- 구조 충족도 100%를 높은 근거 품질로 취급하지 않습니다. 사용자 진술도 외부 검증 사실과 구분해 표시합니다.

## 실패와 재시도

- `narrativeStatus`: 생성 전 `PENDING`, 성공 `READY`, 실패 `FALLBACK`.
- `narrativeError`: `LLM_NOT_CONFIGURED`, `LLM_UNAVAILABLE`, `LLM_EVIDENCE_INVALID`. 브라우저의 통신 실패는 `NETWORK_ERROR`.
- 실패 시 점수 1위에 대한 추천을 만들지 않으며 기본 점검 안내임을 표시합니다. 결과에서 재시도할 수 있습니다.
- 실패 표식은 기존 `result_narrative_json`의 `{"failureCode":"…"}`에 저장해 새로 조회해도 실패 상태를 유지합니다. 성공 시 정상 narrative JSON으로 교체합니다. 추가 DDL은 없습니다.
- 서버의 `config/app.env`에 실제 API 키와 해당 계정에서 사용 가능한 모델 설정이 필요합니다. 예제 키를 자동 발급/대체하지 않습니다. 키나 비밀번호를 로그·저장소·화면 캡처로 공유하지 마세요.

## 모바일

- 터치 기기/모바일의 입력창과 선택 상자는 16px 이상으로 유지합니다.
- 사용자 핀치 줌은 막지 않습니다. 자동 스크롤은 대화 영역 안에서만 이동하며, 칩 선택의 입력 포커스는 페이지를 강제로 스크롤하지 않습니다.
- 비교표와 차트의 가로 스크롤은 카드 안에 한정합니다.
- 자동 테스트는 응답/렌더링/스타일 회귀를 검사합니다. 실제 iPhone Safari의 키보드·포커스·회전 동작은 배포 후 기기에서 추가 확인이 필요합니다.
