# 고민 유형별 결정 지도

## 구현 범위

결과 화면의 `DecisionMapGraph`를 다섯 유형의 Three.js 장면으로 교체했습니다. 기존 API 응답을 그대로 사용하며 DB·백엔드 프롬프트·결정 엔진 점수를 변경하지 않습니다. 3D 코드는 결과 지도가 마운트될 때 별도 청크로 불러옵니다.

| 유형 | 실제 장면 |
| --- | --- |
| career | 대로·교차로·중앙 광장·배경 도시, 입면과 옥상을 갖춘 점수 빌딩·차량·가로수·빛의 경로 |
| travel | 곡선 외곽과 8개 층의 섬·등고선, 발광 항로와 점수에 연결된 이정표 |
| balance | 금속 중심축·보석 허브·곡면 접시, 유광 조약돌 무게추 순차 낙하 |
| purchase | 진열대, 휴대폰·노트북 또는 일반 상자 모형, 기준별 토큰 |
| housing | 집·지붕·생활 경로, 기준별 집과 선택 강조 |

시각 효과는 절차적 기하 도형, RoomEnvironment/PMREM 환경광 반사, 물리 기반 금속·clearcoat 재질, 조명, 그림자, 발광 재질과 움직이는 입자로 구성합니다. 이미지 생성 컨셉의 실사 모델링이나 고비용 후처리 bloom을 그대로 재현한 것은 아닙니다. 네트워크 모델·지도·텍스처 다운로드는 하지 않습니다. 건물의 입면 부품은 geometry를 병합해 draw call을 줄입니다.

## 데이터와 상호작용

- `decisionScene.ts`: 제목·선택지에서 유형 하나를 자동 결정합니다. 일반적인 비용·시간 등의 기준만으로 유형을 결정하지 않습니다. 혼합 의도·미분류 질문은 저울로 고정합니다. LLM 분류가 아니며 결과 화면에서 수동 테마 전환을 제공하지 않습니다.
- `options`: 비교할 두 대안. 후보가 많으면 선택 상자로 변경합니다.
- `criteria`와 `assessments`: 모든 기준별 개체와 점수·중요도 라벨을 동시에 표시합니다. 네 개 라벨 열과 기준 개수에 따른 장면 높이로 겹침을 줄이고, 투영 좌표 연결선으로 개체와 대응시킵니다. 긴 이름은 라벨에서 두 줄까지 표시하되 접근성 이름·툴팁·하단 전체 비교에는 보존합니다.
- `optionProfiles`: 선택한 대안의 장점·부담·대화 근거를 표시합니다. 없는 근거를 생성하지 않습니다.
- 3D 개체, 평면 라벨, 지도 아래 대안/기준 버튼으로 동일한 상세 설명에 접근할 수 있습니다.
- `sceneMetric`: API 평가 점수(0~100)와 중요도를 라벨·3D·비교 카드에서 공유합니다. 커리어 기준 빌딩 높이는 `score / 100 × 3.8`입니다. 여행 표식 기둥과 구매 진열대 높이는 이를 각각 0.5·0.4배로 표현하며, 주거는 집 옆 표식 기둥에 연결합니다. 배경 건물·장식·섬의 크기는 점수가 아닙니다.
- 점수가 클수록 해당 기준에서 유리하다는 뜻이며 성공 확률이나 검증된 사실이 아닙니다. 여행·주거 경로는 실제 거리나 주소가 아닙니다. 0점은 높이 0인 토대, 미확인은 윤곽선 표식과 `미확인` 라벨로 구분합니다.
- 시연 화면의 `가상 고민 선택`은 입력 사례 자체를 바꾸는 테스트 도구이며, 실제 결과의 테마 전환과는 다릅니다.

## 저울 계산

두 대안 모두에 유효한 평가가 있고 중요도가 양수인 기준만 사용합니다.

`기준별 기여도 = normalizedWeight × score / 100`

각 기준에서 두 대안의 기여도를 각각 무게추로 표시합니다. 동일한 조약돌 외피의 크기는 기여도의 세제곱근에 비례해 부피를 맞추며, 기준이 많으면 양쪽에 같은 축소 계수를 적용합니다. 0인 기여도·미확인은 질량 없는 윤곽 표식만 표시하고 라벨을 유지합니다. 작은 장식은 기준 이름에 따라 동전·시계·집·마음·결정체로 바뀝니다. 한쪽 평가가 없어 저울에서 제외된 항목은 하단에 명시합니다.

`최종 각도 = -0.24 × (오른쪽 기여도 합 - 왼쪽 기여도 합) / 비교에 포함된 중요도 합`

오른쪽이 크면 오른쪽 접시가 내려갑니다. 동일하면 수평입니다. 평가가 없거나 한쪽만 있으면 해당 기준을 제외하고 명시적으로 알립니다. 어떤 기준도 비교할 수 없으면 수평 상태에서 자료 부족을 알립니다. `guidance.encouragedOptionId`나 LLM 추천은 무게에 영향을 주지 않습니다.

애니메이션은 약 4.8초 이내로 종료됩니다. 무게추 착지에 따라 빔이 움직이며 접시는 반대 회전으로 수평을 유지합니다. 물리 엔진의 불규칙한 결과 대신 결정 엔진 기여도에 수렴하는 결정론적 애니메이션입니다.

## 성능·접근성

- 기본 시점 고정. 지도 영역 최소 너비 960px, 작은 화면은 해당 영역만 좌우 스크롤합니다. `지도 탐색`을 켠 동안만 3D 팬/핀치 조작을 허용하고 끄면 일반 페이지 스크롤을 유지합니다. 회전은 허용하지 않습니다.
- 확대/축소/초기화는 버튼으로도 가능합니다.
- `prefers-reduced-motion` 또는 사용자 동작 줄이기 선택 시 최종 정지 상태를 표시합니다.
- 애니메이션은 짧게 한 번만 재생하고 이후에는 resize·선택·이동 시에만 렌더링합니다.
- IntersectionObserver와 페이지 visibility로 화면 밖·백그라운드 프레임을 중단합니다.
- 픽셀 비율은 데스크톱 최대 1.5, 좁은 화면 최대 1.25로 제한합니다.
- WebGL 생성/렌더링 실패 및 context loss는 기본 비교 화면으로 전환합니다. 사용자가 직접 2D 보기를 선택할 수도 있습니다.
- 결과 변경·언마운트 시 RAF, 이벤트, observer, 컨트롤, geometry, material, 환경광 render target, 연결선, 그림자와 WebGL 컨텍스트를 정리합니다.

## 확인 방법

1. 프런트엔드 `npm ci` 후 `npm run dev`.
2. `/map-preview`에서 가상 고민을 선택해 자동 유형과 장면을 확인합니다. 실제 결과 영역에는 테마 변경 버튼이 없어야 합니다.
3. 대안/기준을 선택해 상세 근거가 바뀌는지, 2D 전환 후에도 내용이 유지되는지 확인합니다.
4. 저울 재생·최종 균형·동작 줄이기를 확인합니다.
5. 390px 모바일 너비에서 화면 넘침, 선택 상자 글씨, 탐색 모드와 페이지 스크롤을 확인합니다.
6. `npm test`, `npm run lint`, `npm run build`.

자동 테스트는 유형 분류, 혼합 의도, 누락·이상 점수, 대안 순서 반전, 가중치 정규화, 추천과 무게 분리, 다중 대안 선택, 점수-높이 매핑, 전체 점수 동시 표시, 테마 전환 제거를 검사합니다. 실물 iPhone Safari·저사양 GPU에서의 성능은 별도 확인이 필요합니다.

시연 데이터는 `sceneExamples.ts`의 명시적인 가상 사례입니다. 실제 결과 화면에서는 API 결과만 사용하며 시연 문구를 섞지 않습니다.
